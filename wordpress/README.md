# WordPress 소개 본문 · v0.1

사용자가 제공한 Home의 사용자 정의 HTML을 대체하기 위한 검토본. GeneratePress 부모 테마를 수정하지 않으며 별도 CSS 삭제/전역 숨김/JavaScript/외부 리소스 로딩 없음. 클래스 zintro/zi-* 범위 안에서만 스타일 적용. WordPress 관리자 HTML 권한/필터에 따라 style 태그 유지 여부를 실제 미리보기에서 확인한다.

## 범위

소개 본문: 중앙 히어로, 정직한 개발 상태, 비동작 App 화면 구성 예시, 4단계 흐름, 정확히 네 메뉴, FAQ. 기존 헤더·공지·푸터는 페이지 HTML 밖에 있으므로 이 파일만 교체해도 없어지지 않는다. header 구조를 확인한 뒤 따로 정리한다. 로그인/App은 disabled이고 실제 인증/회원가입/발행 없음. 참조 사이트의 이미지·로고·문구·코드를 복사하지 않았다. 실제 참조 폰트는 미확인이며 기존 폰트 상속/시스템 대체에 Pretendard 우선순위만 둔다.

## 적용

기존 페이지 본문은 원본 복사/리비전으로 보존한다. 먼저 별도 초안 페이지의 사용자 정의 HTML 블록에 introduction-block.html 전체 삽입 후 미리보기. 실제 홈 교체는 검토 뒤 진행. 기존 컨테이너 폭·테마 여백·커스텀 CSS가 외부에서 제한할 수 있으므로 사이트에서 확인 필요. 로컬 미리보기는 테마 밖 본문만 확인하는 것이며 WP 적용 완료가 아니다.

## 최신 사용자 확정

growwithzero.com(Cloudways WordPress)을 소개 홈페이지로 재구성. 기존 화면을 보존·재사용하는 제안보다 새 화면 제작이 최신 지시. 네이비 #071226/보라 #7C3AED 유지. 브랜드명은 임시이며 향후 변경. 소개에서 로그인 후 자동 App 이동 금지: 소개로 복귀 후 상단 App 클릭. App은 통합 관리/키워드 발굴/PBN 세팅/백링크 세팅 네 페이지. 2~4에서 준비하고 통합 관리에서 글 작성/WP/PBN/백링크를 실행. SNS 추후. 키워드 로직 임의 개발 보류. Render 최소 유료 운영은 합의, 카드 등록은 다음 날로 보류. Cloudways 사이트 실제 편집 접근 없음, 사용자 화면/제공 본문만 확인.

## 2026-11-13 사용자 적용 결과 / 파일 구성

사용자가 새 본문·Site Footer·Site Header를 적용한 전체 화면을 제공했다. Site Header를 Entire Site로 표시한 뒤 기존 GeneratePress 내비게이션과 중복되는 것을 확인했고, 추가 CSS로 #site-navigation/#mobile-header를 숨겨 새 헤더 한 개 표시를 확인했다. 마지막 화면에는 이전 보라색 ZERO CLOUD 공지 띠가 여전히 있다. 해당 출처는 미확인이며 Elements 목록의 기존 4항목에는 공지 항목이 없었다. 플러그인/스니펫/훅 등 출처 확인 전 광범위 CSS 숨김이나 임의 비활성화 금지.

- header-block.html: 사용자가 적용한 상단 전체 교체 코드의 보관본. Site Header / Entire Site.
- introduction-block.html: 사용자 긍정 피드백과 실제 적용 화면 확인된 본문.
- footer-block.html: 사용자가 적용한 간결한 푸터. Site Footer / Entire Site.
- additional.css: 사용자가 받은 공통 색상·기존 내비 숨김·푸터 하단 배치 코드. 기존 추가 CSS 중 관련 블록만 교체. 다른 CSS까지 삭제하지 않는다.
- build_preview.py: 세 블록을 연결하는 로컬 검토용 HTML 생성기. WP 접근/수정/배포 기능 없음. 실제 WP/캐시/테마 환경 시험을 대체하지 않음.

검토 화면에서 네 메뉴 표기, 로그인/App disabled, FAQ 열기와 로그인 후 소개 복귀 설명을 브라우저로 확인했다. 600px/767px 반응형 CSS는 검토했으나 실제 모바일 기기에서의 확인은 남음. 정책 URL은 사용자가 준 기존 주소를 보존한 것으로 페이지의 존재/내용 적합성은 미확인. 로고는 기존 growwithzero.com 업로드 URL을 사용하며 정식 도메인 변경 시 재설정한다.

## 연결 전 완료/남은 것

완료 증거: 소개/상단/하단 사용자 적용 스크린샷. 내부 기반은 기존 중앙 API 코드와 모의 테스트 증거이며 실제 서비스 연결이 아니다.

남음:
1. 보라색 공지 띠 원본 찾아 비활성화. 관련 없는 플러그인/보안 기능을 추측으로 끄지 않음.
2. PC/모바일, 메뉴 앵커, 기존 개인정보/약관 주소 실제 접속 검토.
3. 현재 중앙 App을 합의한 네 메뉴로 재구성. 초기에는 통합 관리의 WP/데이터 기능만 실제 활성, 키워드 발굴/PBN/백링크 로직은 준비 중.
4. Render 카드 등록 후 기존 Blueprint 최소 자원 최종 비용 확인·배포. 실제 DB 연결/동시성/재시작 검증 필요.
5. 로그인/회원은 Render 중앙 시스템. WordPress 로그인 버튼 → 중앙 인증 → 소개로 돌아옴 → 사용자가 App 클릭. 현행 owner-password API만으로 교차 도메인 SSO가 완성된 것은 아니다. WordPress 로그인 표시와 중앙 세션을 연결하는 서버 간 검증/상태/복귀 URL 허용목록을 별도 구현해야 한다. 비밀번호나 장기 토큰을 URL/localStorage에 넣지 않는다.
6. 초기 운영자 본인만 로그인, 고객 공개 회원가입은 아직 열지 않음. 완료되지 않은 가입/로그인 버튼을 활성화하지 않음.

## 원상 복구

GeneratePress 리비전/기존 본문을 먼저 확보. 새 Site Header를 비활성화할 경우 additional.css의 두 기존 메뉴 숨김 선택자를 함께 제거하여 기본 메뉴 복원. 푸터/본문은 해당 블록의 이전 리비전 복구. 중앙 키워드/작업/초안 DB는 이 페이지 교체와 무관하며 삭제하지 않는다.
