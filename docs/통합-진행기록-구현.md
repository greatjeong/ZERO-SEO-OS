# 통합 관리: 진행 기록·확인 상태

2026-11-14 KST. 사용자 요청에 따라 실제 앱 화면 통합 다음으로 A-02의 운영 기록 확인 동작을 구현했다. 기술 주 단계는 진행 중이다. 네 메뉴·원래6단계 의미는 유지한다.

## 동작

통합 관리의 ‘진행 기록 불러오기’에서 저장된 검색·RSS 수집·키워드 변경/작성 준비 연결 기록을 모아 보여준다. 검색·RSS·키워드별 최근20개, 최대60개 범위만 읽으며, 그 이전 기록이 있으면 따로 표시한다. 전체 작업 수/성공률/현재 미해결 장애 통계가 아니다.

- 조회 전은 미조회. API가 빈 목록을 반환했을 때만 표시할 기록 없음.
- 기록 당시 ‘확인 필요’, ‘검토 대기’, ‘기록됨’을 구분. 결과 수신은 최종 키워드 합격이나 글 발행 성공이 아니다.
- pending 검색은 결과 미확정으로 표시한다. 프로세스가 실제 실행 중인지 알 수 없으므로 실행 중/진행률을 꾸며내지 않는다.
- RSS 오류는 허용 목록의 안전한 이유로 안내한다. 원래 공급자 오류 문자열/키/HTTP 헤더/임의 이벤트 세부 메모를 화면으로 보내지 않는다.
- 일부 영역의 JSON 기록을 읽지 못하면 미확인 영역과 부분 건수 경고를 표시한다. 조회 실패 후 이전 화면 기록도 유지한다.
- ‘해당 단계 열기’는 키워드 화면의 검색/RSS/DB 영역으로 이동하고 기록 불러오기 안내를 표시한다. 검색·수집·AI 작업을 재실행하지 않는다. 유료 API 자동 재시도 없음.
- 필터는 화면에서 읽은 목록만 처리한다. 별도 네트워크나 저장 요청을 발생시키지 않는다.

## 구현과 보존

로그인 필요한 GET `/api/activity`와 `central_activity.py`, React `CentralActivity`를 추가했다. 기존 테이블을 읽기만 하고 새 테이블·기록 삭제·작업 상태 변경은 없다. 개별 작업의 최신 근거/원본 DB는 해당 단계에서 확인한다. 작성 준비 연결 이벤트는 실제 글 생성·저장·발행 없음 문구와 함께 표시한다. 메뉴 전환 시 기존 폼과 후보는 유지한다.

기존 WP 연결·초안737/738·.state·workspace·백업 호환·키워드 자산은 변경하지 않았다. Render·SerpApi·실제 RSS·WP 요청은 이번 작업에서 실행하지 않았다. 정적 Sites 시뮬레이션도 수정하지 않았다.

## 검증

신규 서버8개: 빈 목록/읽기 전용, 양쪽 일부 실패·pending 의미, 허용된 오류 안내·민감 세부 메모 비노출, 작성 준비 의미·원본 보존, 최근20개 범위, 손상된 영역의 부분 경고, 로그인·GET 전용을 검증한다. 신규 화면4개: 명시적 조회, 실패 후 기존 목록 유지, 부분 경고/로컬 필터, 해당 단계 이동이 쓰기·재검색 없이 작동하는지 검증한다.

전체 회귀 결과는 검증 완료 후 이 문서 마지막에 기록한다. TypeScript/Vite 빌드, Python compile, 공백 검사 통과. 브라우저 픽셀·모바일 검증과 Render/SerpApi/운영PG 실제 통합 시험은 사용자 요청대로 이후 진행한다.

최종 내부 회귀: 서버127개·화면36개 모두 통과. 외부 시스템 실제 연결이나 배포 성공을 뜻하지 않는다.
