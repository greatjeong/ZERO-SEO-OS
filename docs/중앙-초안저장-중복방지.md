# 중앙 테스트 초안 저장 · 2026-11-13

A-02 사이트 관리의 사용 흐름과 A-03/A-04 선행 연결 기능. 전체 단계 완료·AI 글 생성·운영 배포를 의미하지 않는다. 운영화면 시안은 별도 검토 자료이며 실제 기능 구현 상태와 구분한다.

## 사용자 동작

- 기존 737·738 같은 테스트 초안이 있으면 이력에 먼저 등록하고 기존 글 상태 확인을 사용한다. 기존 기록이 하나라도 같은 URL에 있으면 새 테스트 초안 생성 차단. null ID도 차단 대상이다.
- 새 대상은 기존 PC 기록 확인 체크 + 대상 URL을 명시한 저장 확인을 거쳐 고정된 연결 테스트 글 1개를 draft로 저장한다. 공개·예약 발행 없음. 이 체크는 실제 이관 완료의 증거가 아니며, 사용자가 누락한 외부 기록까지 자동 발견할 수는 없다.
- 서버는 매 요청마다 인증된 사용자의 edit_posts=True를 조회하고, 저장된 URL·인증정보 세대가 바뀌지 않았는지 확인한다.
- URL을 기본키로 한 저장 intent를 트랜잭션으로 먼저 커밋한 다음 POST를 한 번만 보낸다. A-1/A-2가 같은 URL이면 같은 intent를 사용한다. workspace/인증정보 변경·이력 가져오기와 같은 DB 잠금을 사용한다.
- 반환된 글 ID를 먼저 기록하고 응답 draft 상태 검사 후 별도 GET으로 같은 ID·draft 상태를 확인한다. 이 확인이 성공한 경우에만 화면에 확인 시점 기준 성공 표시.
- DB 쓰기 실패, timeout, 프로세스 종료 등 결과가 불확실하면 intent를 지우거나 POST를 자동 재시도하지 않는다. ID가 있으면 읽기 전용 재확인. ID가 없으면 글 목록에서 수동 확인 필요. 자동 잠금 해제·ID 추측·글 삭제·새 글 대체 기능 없음.
- 저장 시도 기록 조회는 마지막 확인 시점을 현재 성공으로 간주하지 않는다. 다시 확인할 때 실패하면 기존 화면 성공 표시 제거.

## 검증

서버 88개·화면 19개 통과, 빌드·lint·Python compile·diff 검사 통과. 모의 WP/임시 SQLite로 동시 요청 단일 POST, 실제 요청 본문 status=draft, POST 후 별도 GET, timeout 후 재시도 차단, ID 보존 후 재조회 복구, 서버 재시작 및 같은 URL 다른 슬롯 차단, 기존 이력/null 차단, capability 누락·명시 확인 누락·CSRF 차단, 비초안 응답 거부를 검사했다.

기존 로컬 기능·.state·키워드·작업·JSON은 수정/초기화하지 않았다. 실제 사이트 요청·추가 글 생성·실데이터 이관·유료 자원 생성 없음. PostgreSQL은 기존 dialect 준비만 있으며 새 intent의 실제 PG 동시성/재시작과 브라우저 E2E·두 PC 배포 시험은 남아 있다. 키 분실 복구/회전 도구와 null intent의 검증된 운영자 수동 해결 절차도 남아 있다. DB를 원본 이력 없이 새로 만들면 기존 WordPress 글을 자동 파악할 수 없으므로 이전 DB/이력을 먼저 복구해야 한다.
