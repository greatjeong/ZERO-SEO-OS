# 실제 중앙 앱 화면 통합

2026-11-14 KST. 사용자 승인: 준비된 기능을 왼쪽·상단 메뉴가 있는 실제 앱 레이아웃에 연결한다. A-02 화면·흐름 구현이며 전체 단계 완료나 실제 운영 배포가 아니다. 기존 static Sites 시뮬레이션은 그대로 두고 React 중앙 앱 소스에 적용했다.

## 메뉴와 배치

- 통합 관리: 사이트 주소 입력 요약, 기존 등록 키워드 수(발굴 DB와 구분), 원본 글 작성 준비 조회, A-1/A-2 설정, WP 비밀 저장·연결 확인, 초안 이력·중복 방지 테스트 도구, 기존 수동 키워드·작업·백업 복원 기능.
- 키워드 발굴: 1~2 검색 입력·양쪽 결과·유형 검사, 3 RSS 수집·후보 편집, 4~5 선별·DB·재검증·내보내기. 기존 KeywordBank 컴포넌트는 `showPreparations=false`로 6단계 목록을 이 페이지에 중복 배치하지 않는다.
- PBN 세팅·백링크 세팅: 준비 중 안내. 실제 연결·작업 버튼이나 실행 결과를 꾸미지 않는다. 메뉴명/세부 레이아웃은 사용자 검토에 따라 수정 가능하다.
- 상단: 현재 메뉴명·설명·본인 계정 표시·사용법. 공통 저장 상태·저장/새로 불러오기/로그인 갱신·로그아웃 유지. 네이비 #071226, 퍼플 #7C3AED. 전폭 사용; 고정/스티키 헤더 없음.
- 메뉴 접기와 좁은 화면 메뉴 열기/닫기. 좁은 화면에서는 메뉴 선택 후 닫힘. 현재 메뉴 aria-current와 접힌 상태에서도 접근 가능한 이름 유지. 키보드 focus 표시. 실제 모바일 브라우저는 아직 미검증.

## 보존과 상태 표시

메뉴 전환 시 dashboard와 한 번 연 keyword 화면을 hidden으로 보존해 입력/선택/불러온 기록을 지우지 않는다. 키워드 화면은 첫 진입 때만 마운트하므로 최초 로그인에서 검색 API 상태 조회를 강제하지 않는다. PBN/백링크 이동은 데이터 저장/외부 요청을 발생시키지 않는다. 기존 workspace/로그인/CSRF/JSON 및 WP 도구 API는 변경하지 않았다.

원본 글 작성 준비는 조회 전 `미조회`, 빈 결과를 확인하면0. 주소가 입력됐다는 이유로 인증 완료·연결됨을 표시하지 않는다. 통합 관리에서 준비 목록을 조회할 수 있고, 키워드 DB에서 불러오기/검토/연결 후 받은 동일 목록은 콜백으로 통합 관리 요약에 전달한다. 실제 AI 글 생성 여부와 별개다. 작업 공간 저장/재조회 후 준비 목록의 적격 여부를 다시 확인하도록 목록을 미조회로 바꾼다.

기존 UI 컴포넌트의 기본 `showPreparations=true` 동작은 보존해 독립 사용·기존 테스트 호환을 유지한다. 서버가 준비 목록 배열을 주지 않으면 형식 미확인으로 남긴다.

## 확인 결과와 한계

- 화면 테스트32개(기존27+신규5) 통과. 메뉴 이동 후 미저장 사이트 이름 유지, keyword 입력 유지/단일 마운트, 준비 목록 미조회와 적격 차단 상태, 접힌/모바일 메뉴 접근성 상태, 키워드 DB 조회 기록의 통합 관리 전달·중복 목록 제거 확인. TypeScript/Vite 빌드 및 git diff 공백 검사 통과.
- 백엔드 코드 변경 없음. 이전119개 서버 테스트 결과를 이번 실서버 테스트로 재사용해 주장하지 않는다.
- 읽기 전용 예시 데이터의 로컬 UI QA 서버를 만들고 브라우저로 열기를 시도했으나 `ERR_CONNECTION_REFUSED`. 브라우저에서 데스크톱 배치/픽셀·반응형을 직접 확인하지 못했다. 따라서 DOM 검증과 CSS 구현을 실제 브라우저 검증으로 부르지 않는다. QA 서버는 운영 앱이 아니고 인증·검색·발행 모두 실행하지 않았다.
- Render 배포, 실제 공급자 검색/RSS, 운영PG/두PC, 소개사이트↔로그인 복귀 브리지, 최종 앱 경로/도메인 연동은 이후 한 번에 검증. 사용자에게 카드/키를 지금 다시 요청하지 않는다.
- 기존 WordPress/Sites 시뮬레이션·사용자DB/.state 변경 없음. 현재 코드는 GitHub에 저장하고 실제 배포는 보류한다.
