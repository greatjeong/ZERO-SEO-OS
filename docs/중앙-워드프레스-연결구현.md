# 중앙 WordPress 연결 첫 구현 · 2026-11-13

주 단계 A-02 진행 중. 사이트 관리 화면을 중앙 API에 연결하는 A-03 선행 묶음이다. Render 결제수단 등록은 보류됐으며 실제 서비스·PostgreSQL은 생성하지 않았다.

## 구현

- 로그인 + Origin/CSRF 검증을 통과한 소유자만 사이트별 앱 비밀번호 등록과 읽기 전용 인증 확인 가능.
- 서버의 ZERO_WP_ENCRYPTION_KEY(Fernet 키)로 사용자명·앱 비밀번호·사이트 주소·슬롯을 함께 인증 암호화. DB에는 암호문과 무작위 세대 ID만 저장. 로그인 비밀번호와 암호화 키는 분리한다.
- 키가 없으면 관련 API만 503으로 차단. 기존 중앙 로그인·워크스페이스는 계속 동작. 잘못된 키로 복호화 실패 시 기존 암호문을 덮어쓰거나 삭제하지 않는다.
- 키는 별도 서버 비밀 설정으로 보관하고 DB 백업과 분리해 안전하게 복구 가능하도록 보관해야 한다. 생성은 cryptography.fernet.Fernet.generate_key() 사용. 키 분실 시 기존 자격 복구 불가. 키 회전 운영 도구는 아직 없다. 자동 생성 후 재시작마다 교체하지 않는다.
- 일반 JSON·워크스페이스 저장본·API 응답에 인증정보를 포함하지 않음. UI 비밀번호 입력은 요청 종료 시 지움. localStorage/sessionStorage 사용 안 함.
- 사이트 URL은 저장된 워크스페이스에서만 읽음. 변경 후 이전 자격 사용 차단. 확인 중 자격 교체도 성공 반환 차단.
- 기존 v0.2.5의 DNS 공개 IP 검증·IP 고정 HTTPS·표준 TLS 검증·리다이렉트 차단 코어 재사용. 인증 확인은 GET users/me만 수행하며 글 생성/변경 없음.
- 인증과 사용자 권한 확인에 성공한 응답이 있을 때만 확인 시점 기준 성공 표시. 저장만 해서는 연결 완료 표시 안 함. 권한 필드 누락은 미확인. 새 요청 실패 시 이전 성공 표시 제거.

## 검증과 남은 범위

임시 SQLite/모의 WordPress로 암호문 저장, 재시작, 백업 제외, 잘못된 키, 주소 변경, 동시 자격 교체, 인증 실패, 로그인/CSRF 차단을 검사한다. 실제 사이트 요청은 하지 않았다. 실제 PostgreSQL·두 PC·브라우저 E2E는 아직 미검증이다.

기존 App, 로컬 server.py, backend/.state와 초안 738은 수정하지 않았다. 중앙 초안 생성은 아직 제공하지 않으며, 기존 737/738 초안 이력의 안전한 이관·중복 방지부터 구현해야 한다. 자동 AI 생성·공개 발행·유료 SaaS는 이번 범위가 아니다.

다음: 초안 이력 가져오기 미리보기/원자적 보존 → 읽기 전용 기존 초안 확인 → 중앙 초안 중복 방지와 명시적 저장. 사용자 실제 백업 파일이 없으므로 데이터 이관 완료라고 표현하지 않는다.
