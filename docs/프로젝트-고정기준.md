# ZERO SEO OS 프로젝트 고정 기준

2026-11-13 · 사용자 확정 사항의 기준 문서

이 문서는 이미 합의한 내용을 매번 다시 묻거나 개발 방향을 바꾸지 않기 위한 것이다. 현재 구현 수준·버그·시험 결과와 앞으로 검토할 기술 선택은 별도 문서로 관리한다. 아래 확정 사항은 사용자가 명시적으로 변경할 때만 변경하며, 새 제안을 작성했다는 이유로 기존 합의를 대체하지 않는다.

## 1. 서비스는 세 영역으로 구성한다

| 영역 | 확정한 역할 |
|---|---|
| 소개 홈페이지 | ZERO SEO OS 소개·기능 안내·고객 유입·가입 연결 |
| App | 로그인 후 현황판·키워드·사이트·작업을 관리하는 웹앱 화면 |
| SaaS 운영 시스템 | 계정·권한·영속 데이터·Python 자동화 작업을 중앙에서 처리 |

App과 중앙 운영 시스템을 함께 묶어 SaaS 서비스를 제공한다. App을 PC마다 설치하는 전용 데스크톱 프로그램으로 임의 재정의하지 않는다. 세 영역을 반드시 서버 세 대 또는 별도 유료 제품 세 개로 만들기로 결정한 것은 아니다.

## 2. 기존 기술과 중앙 운영 목표

- 기존 React + TypeScript 화면과 Python 연결·자동화 코어를 유지·활용한다.
- Cloudways에 맞추기 위해 PHP/Laravel로 다시 작성하는 방향은 선택하지 않았다. 이 문제를 이미 정한 방향의 대안으로 반복 질문하지 않는다.
- 목표는 PC에 매번 서버 창을 켜는 방식이 아니라, 중앙 서비스 주소에 로그인하면 같은 데이터를 이어 쓰는 웹 서비스다.
- 현재 로컬 실행은 연결 기능을 검증하기 위한 단계다. 로컬 시험 성공을 중앙 SaaS 완성으로 표현하지 않는다.

## 3. 첫 사용 범위

- 첫 중앙 버전은 사용자 본인만 사용하는 비공개 서비스다.
- 이후 고객용 확장을 고려하되 현재 범위를 고객 공개·유료 결제·구독 출시로 임의 확대하지 않는다.
- `본인용으로 시작할까요?`, `처음부터 고객용인가요?`를 다시 묻지 않는다.

## 4. 테스트 대상과 서비스 서버를 분리한다

| 대상 | 확정 기준 |
|---|---|
| 테스트 WordPress | 기존 https://a.webcreatorlabs.com · Cloudways에 유지 |
| ZERO SEO OS | Python을 지원하는 별도 중앙 운영 환경을 선정 |
| Cloudways의 의미 | 테스트 대상 WP의 호스팅. ZERO SEO OS 호스팅을 Cloudways로 제한하지 않음 |

사용자는 “꼭 Cloudways를 사용할 필요는 없고, 테스트 WordPress가 그곳에 있을 뿐”이라고 정정했다. 따라서 Cloudways PHP 환경에 Python 서비스를 맞추기 위한 논의를 되풀이하지 않는다. 테스트 대상 WP와 SaaS 서버가 같은 제공자·IP·지역일 필요는 없다.

## 5. 데이터와 인증정보

- 기존 기능·사이트·키워드·작업·JSON 복원 호환·초안 중복 방지 기록을 보존한다.
- 인증정보를 프론트엔드 저장소·소스·GitHub·일반 JSON 백업에 저장하지 않는다.
- 중앙 운영에서는 서버 측 보안 저장·소유권·백업·이관을 구현한다. 구체 제품·키 관리 방식은 미확정이며 검토 사실만으로 구현 완료라 부르지 않는다.
- 기존 PC의 브라우저 데이터와 backend/.state는 가져오기 검증 전 삭제·초기화하지 않는다.
- 실제 WordPress 변경 테스트는 사용자가 승인한 범위에서만 수행한다. 승인 범위를 반복 질문하지 않되, 기존 승인과 다른 공개 발행·삭제·새 대상 변경으로 확대하지 않는다.

## 6. 로드맵과 진행 방식

- 기술 A-01~A-04 및 PHASE B~E와 사업 전체 01~13을 구분한다. 기존 단계명·순서·완료 기준을 임의 재정의하지 않는다.
- A-1/A-2는 사이트 슬롯, 버전 번호는 코드 버전이다. 이들을 개발 단계와 혼동하지 않는다.
- 기술 주 단계는 현재 A-02 진행 중이다. A-1 연결·초안 성공으로 전체 단계나 SaaS 완료를 선언하지 않는다.
- 사용자는 비개발자다. 작업을 직접 수행하고 안내가 필요하면 한 단계씩 제공한다. 터미널 입력·여러 파일 교체·같은 자격 입력을 근거 없이 반복시키지 않는다.
- 기존 합의와 구현 범위 안의 조사·코드 점검·가역적 수정·적절한 테스트·Git 저장은 자율적으로 진행한다.
- 주요 아키텍처·실제 운영 환경·유료 자원·권한·실사이트 변경의 새 선택이 필요한 경우에만 구체적인 검토 결과와 이유를 제시한다.

## 7. 확정하지 않은 사항 — 확정 사항과 혼동 금지

현재 미정은 다음과 같다. 조사·추천안을 만들 수 있으나 확정된 척하지 않는다.

- Python 중앙 서비스를 운영할 실제 제공자·상품·요금과 서비스 도메인.
- 중앙 웹 프레임워크·DB 제품·로그인 구현·비밀 저장 방식.
- 비공개 서비스의 실제 배포 대상과 접근 계정 구성.
- 고객 공개·요금제·결제·AI 자동 작업·공개/예약 발행의 후속 범위.

미정 사항을 해결하려고 이미 확정한 Python 유지·본인용 비공개·세 영역 구성을 다시 선택하게 하지 않는다. 구현을 막지 않는 세부 기술 선택은 근거 있는 추천과 범위 내 작업으로 진행하고 불필요하게 사용자에게 떠넘기지 않는다.

## 8. 매 작업 시작 시 적용 절차

1. 이 문서와 개발기준-로드맵.md, 최신 검증 기록을 읽는다.
2. 지금 요청이 확정 사항의 실행인지, 새 결정인지, 사용자의 명시적인 기존 결정 변경인지 구분한다.
3. 확정 사항은 질문 없이 적용한다. 검토 문서를 확정 사실로 승격하지 않는다.
4. 문서 간 모순은 사용자의 최신 명시 발언과 이 기준에 맞춰 정리한다. 이미 정정된 이전 문서 때문에 같은 질문을 다시 하지 않는다.
5. 새 발견이 기존 방식을 기술적으로 막는다면 증거·영향·보존 가능한 부분을 설명한다. 대안을 조용히 확정하거나 사용자가 입장을 바꿨다고 기록하지 않는다.
6. 작업 결과·남은 실제 결정·검증 증거를 기록하고 GitHub에 반영한다.

이 기준 문서는 사용자 지시를 대체하는 규칙이 아니다. 사용자가 명시적으로 변경하면 변경 이유와 영향을 기록해 갱신한다. 단순한 버그·버전·테스트 결과는 별도의 진행 기록을 갱신하며 전체 기준을 다시 협의하지 않는다.
