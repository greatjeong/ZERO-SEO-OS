# 독립 진행 6항목 구현·검증 · 2026-11-24

사용자가 독립 진행 가능한 여섯 항목을 질문 없이 모두 구현하고, 이후 확인할 기능만 안내하도록 승인했다. A-02 화면/사용 흐름 보완과 기존 PHASE C/D 기능의 공통 처리 코어를 선행 구현했다. 주 단계는 A-02 진행 중이다. 최종 승인 네이비 UI·메뉴·기존 기록 유지. 실서비스 검색·AI·WP·PBN·백링크 외부 실행은 켜지 않았다.

## 사용자 화면에서 확인할 곳

- 사이트 연결·세팅 맨 아래: **작업 데이터 보관·복구 → 작업 관리 불러오기**. 보관본 내보내기·파일 가져오기 미리보기·추가/동일/충돌 보존 건수. 복구는 확인 후 누락 행만 추가한다.
- 원본 글 작성 맨 아래: **작업 준비·연결 설정·모의 검증 → 작업 관리 불러오기**. 연결 준비 설정, 준비 대기열, 외부 연결 없는 모의 검증.
- 키워드 발굴 맨 아래: 동일 준비 설정·대기열·모의 검증. 검색량 제공처 이름을 저장해도 실제 API는 연결되지 않는다.
- PBN 세팅 / 백링크 세팅 맨 아래: **후보·원본 연결·결과 관리 → 작업 관리 불러오기**. 원본/대상 URL 등록, 후보/검토/준비/제외/직접 결과 기록, 이력 및 준비 작업.
- 기존 적격 작성 준비에서 원본 글 작업을 연 경우: **원본 글 이전 버전 보기 → 비교·복원 준비 → 비교 확인 후 복원**. 서버 저장본 기준 문서 내보내기·형식/반복 검사·작업 등록·다시 불러오기. 아직 적격 작성 준비가 없으면 실제 편집 기능은 이후 검색 데이터 연결 때 확인한다. 없는 글을 실제 글인 것처럼 채우지 않는다.

## 보관·복구 범위

작업 공간 이력, 검색/RSS, 키워드/출처/이력, 작성 준비, 원본 문서/버전, 가이드/설정, 후보 관계, 연결 준비 설정을 archive에 포함한다. 인증·세션·로그인 시도·실행 중 작업·WP 초안 중복방지/전송 intent는 제외한다. 이것은 **작업 데이터 보관본이며 DB 전체 재해 복구 백업은 아니다**. 전체 DB/암호화 키 보관은 별도 운영 작업이다. 보관본은 고객 데이터가 포함될 수 있으므로 본인 계정만 다운로드/가져오기 가능하다.

가져오기는 한 파일 5MB·10000행 이하를 지원한다. 대용량 전체 DB는 별도 DB 백업 도구로 다룬다.

restore는 인증정보나 기존 행을 교체하지 않고, 현재 없는 PK만 추가한다. 충돌은 건수 표시 후 보존. 원본 글 이전 버전 적용은 별도의 문서 복원 API가 새 revision을 생성한다. 미리보기 이후 DB 변경 시 basis 비교로 중단한다. 외부 실행 중복방지 기록을 복구본으로 되돌리거나 초기화하지 않는다.

## 실행과 결과 표시

- production에는 AI/검색량/원본 WP transport를 설치하지 않았다. 준비 설정의 제공자·모델 이름은 메모이며 활성화 설정이 아니다.
- 준비 작업은 blocked. 모의 작업만 queued→running→succeeded/failed로 처리한다. 실제 외부 worker/스케줄은 없다.
- 모의 lease가 만료되면 claim 재시도 시 unknown으로 전환하고 자동 재실행하지 않는다. 실제 실행 작업의 결과 불확실성과 자동 재시도는 이후 제공자별로 검증해야 한다.
- 원본 초안 adapter는 검토된 문서 버전에 대해 durable intent를 먼저 쓰고 POST 결과 ID를 보존한 뒤 GET 재조회한다. 불확실 요청은 재전송하지 않는다. 현재 이것은 주입형 시험 adapter이며 실서비스 WP 본문 변환·인증·전송 UI는 후속 연결 범위다.
- 형식·반복 검사는 SEO/AEO/GEO 지침의 편집 보조다. 사실 검증·원본성 인증·순위/색인 보장을 하지 않는다.
- network 직접 결과 기록은 자동 등록/실제 링크 검증 성공이 아니다. 링크 검사 코어는 주입 계약만 있으며 운영 HTTP 점검은 켜지 않았다.

## 검증 기록

- 기존+신규 서버 전체170개 통과. 새 기능 서버17개(동시 claim, lease/retry, 다른 DB 복구, mock pipeline, 원본 초안 불확실 재전송 방지, 권한 등).
- UI 전체50개 통과. 신규5개: 후보 입력 실패/메뉴별 보존, 설정 재조회 불일치, 복구 미리보기/취소, 모의 결과 구분, 버전 비교·복원 실패 보존.
- TypeScript/Vite 빌드 통과. PostgreSQL 신규 table 컴파일 검사와 기존 PostgreSQL URL/dialect 회귀가 있으며 실제 운영 PG에서 전체 복원/동시 worker 시험을 완료했다는 뜻이 아니다.
- 브라우저는 저장소 밖의 격리 fixture로 후보 저장·모의 검증 결과와 승인 레이아웃 유지 확인. QA 스크립트는 Git/운영 빌드에 포함하지 않았다.
- 실제 검색/API/WordPress 요청·발행·DB 데이터 가져오기/삭제·설정 변경은 수행하지 않았다. 배포 자체의 새 테이블 생성 외에 사용자 데이터를 변경하지 않는다.

## 나중에 사용자와 확인할 사항

1. 저장된 후보·메모·설정의 새로고침/재로그인 유지, 화면 동선과 이름.
2. 기존 작성 준비가 있는 문서의 내보내기·비교·복원, 검토 해제 및 이전본 보존.
3. 모의 검증 결과와 실제 성공의 구분.
4. 데이터 보관본 범위/충돌 건수·복구 동선. 실제 DB 전체 백업과 별개임을 확인.
5. 이후 실제 검색량 제공처/AI 모델·비용/분량·말투, WP 대상, PBN 언어·수량·주기 및 백링크 실제 대상/방식 결정 후 외부 통합 시험. 현재 결정을 재촉하지 않는다.

고객 다중 사용자 격리·결제·SNS·공식 지표 연동·실제 PBN/백링크 실행·공개/예약 발행은 이번 공통 코어 개발만으로 완료되지 않는다. 주 단계 A-02 유지.
