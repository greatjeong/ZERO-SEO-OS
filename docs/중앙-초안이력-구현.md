# 중앙 기존 초안 이력 · 2026-11-13

기술 주 단계 A-02 진행 중, 사이트 관리의 A-03/A-04 선행 기능. 실제 Render·PostgreSQL 배포와 사용자 데이터 이관은 아직 수행하지 않았다.

## 구현한 흐름

1. 서버에 저장된 사이트 정보에서 기존 WordPress 글 ID를 직접 입력하거나 전용 이력 JSON 선택.
2. 사이트 주소·글 ID·출처별 미리보기 후 사용자 확인. 미리보기는 DB·WordPress 변경 없음.
3. 중앙 DB에 추가 보관. 기존 이력은 삭제·교체하지 않음. 내용 fingerprint로 동일 기록 재가져오기 중복 방지. 같은 URL의 737·738 및 출처가 다른 이력을 각각 보존. null ID는 불확실 상태로 보존.
4. 조회한 목록을 전용 이력 JSON으로 다시 내보내기 가능. 일반 키워드/작업 백업과 구분. 인증정보·글 본문은 포함하지 않음.
5. 등록된 인증정보와 정확히 같은 사이트의 기존 ID만 GET 조회. 응답 ID와 draft 상태를 확인한 경우에만 확인 시점 기준 초안 확인 표시. 게시 상태가 달라졌거나 통신 실패·불확실 ID는 성공 표시하지 않음. 어떤 실패에도 새 글 생성·기존 글 수정·삭제 없음.

## 이력 JSON 형식

format: zero-seo-os-draft-history, version: 1, records 배열(1~500개).
각 항목은 url(HTTPS), postId(양의 정수 또는 null), createdAt(원본 시점 문자열 또는 미확인 표시), source(출처 문자열)만 허용. 예상 밖 필드/잘못된 항목은 전체 요청 거부. 전체 추가는 한 DB 트랜잭션이고 기존 키워드·작업·사이트 저장본과 분리한다. 전용 SQLite DB 파일을 업로드해 실행/변경하는 기능은 제공하지 않는다. 기존 .state 원본은 유지한다.

## 검증

서버 81개, 화면 17개 테스트 통과. 빌드·lint 통과. 모의 WP 테스트는 GET /posts/738?context=edit 외에 쓰기 요청이 없음을 검사했다. 미리보기 취소, 반복 가져오기, 잘못된 항목 원자적 거부, 737/738/null 보존, published 상태 거부를 검사했다. 기존 로컬 기능 회귀 포함.

사용자 PC의 실제 백업/.state 파일은 Work에 없으므로 실제 이관 완료 아님. 실제 WordPress 요청과 추가 글 생성은 하지 않았다. 실제 PG/다중 PC/브라우저 E2E 미검증.

다음: 중앙 초안 생성 전에 사이트별 이력·불확실 intent를 검사하는 중복 방지와 durable intent를 구현. 실제 초안 추가 테스트는 기존 738을 재사용하는 확인과 구분하고 사용자 승인 범위 내에서만 수행. AI 생성·공개/예약 발행은 아직 범위 밖.
