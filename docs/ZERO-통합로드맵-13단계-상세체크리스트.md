# ZERO 통합 실행 로드맵 상세 체크리스트

2026년 11월 12일 정리 · 검토용 초안

이 문서는 사용자가 제공한 「통합 실행 로드맵 13단계」 이미지의 단계명과 핵심 체크 항목 53개를 유지하고, 실행할 작업과 완료 조건을 덧붙인 문서입니다. 예전 Word 마스터 플랜을 복구한 문서가 아닙니다. 각 항목 아래의 세부 내용은 이번에 구체화한 제안이며, 해당 단계에 착수하기 전에 범위를 확인합니다.

목적은 새 기능을 계속 늘리는 것이 아니라, 무엇을 만들고 어떤 증거가 있어야 완료로 볼지 기준을 정하는 것입니다. 미체크는 모두 미개발이라는 뜻이 아니라, 그 항목 전체의 완료를 아직 확인하지 않았다는 뜻입니다. 전체 진행률은 임의로 계산하지 않습니다.

## 번호를 구분하는 기준

| 표기 | 뜻 |
|---|---|
| 전체 01~13 | 이번 이미지의 사업 전체 실행 로드맵 |
| 기술 A-01~A-04 | 별도 SaaS 시스템 기반 구축 개발표 |
| 사이트 A-1 / A-2 | 등록한 워드프레스 사이트 구분 |
| v0.2.2 | 현재 코드 배포 버전 |

기존 기술 개발 기록의 주 단계는 **A-02 진행 중**으로 유지합니다. 현재 만든 콘텐츠 관리·워드프레스 연결은 전체 로드맵의 08번과 관련된 구현이지만, 이를 이유로 전체 01~07이 완료됐거나 전체 08이 완료됐다고 판단하지 않습니다. 두 로드맵은 번호를 합치지 않고 따로 관리합니다.

## 전체 01 브랜드 기반 구축

목표: 브랜드와 운영 환경을 정리하고, 복구 가능한 워드프레스 기반을 준비합니다.

- [ ] **01-1 도메인·호스팅·SSL 설정**
  대표 브랜드명·도메인·관리 계정·결제 주체를 기록합니다. DNS와 HTTPS, 대표 주소 통일, 테스트 사이트와 운영 사이트의 구분을 확인합니다.
- [ ] **01-2 워드프레스 설치·기본 설정**
  사이트 제목·언어·시간대·고유주소·관리자 계정을 정리합니다. 검색 공개 여부와 기본 페이지를 확인하고, 운영 정보를 한 곳에 기록합니다.
- [ ] **01-3 테마·필수 플러그인 구성**
  실제 사용할 테마와 플러그인만 선정하고 역할·설정·버전을 기록합니다. 중복 기능과 불필요한 항목을 정리하고, 업데이트 시 확인할 항목을 정합니다.
- [ ] **01-4 보안·백업·기본 최적화**
  권한·인증정보 관리 방법과 백업 주기·위치·보관 기간을 정합니다. 테스트 환경에서 백업 복원을 확인하고, 캐시·이미지·기본 모바일 표시를 점검합니다.

완료 조건: 대표 주소로 접속되고, 운영 설정표와 백업·복구 절차가 있으며, 복원 시험 결과를 확인할 수 있습니다.

현재 기록: 이전 ZERO BUSINESS 대화에 기반 구축 완료 인수인계가 있습니다. 현재 ZERO SEO OS 코드의 개발 상태와 동일시하지 않으며, 적용 대상 사이트를 구분해 대조합니다.

## 전체 02 사이트 기획 뼈대 설계

목표: 누구에게 무엇을 제공하며, 방문자가 어디로 이동해야 하는지 확정합니다.

- [ ] **02-1 사이트 목표·타깃·콘셉트 정의**
  핵심 고객, 고객 문제, 제공 가치, 대표 상품·서비스를 한 문서로 정리합니다. 사이트의 첫 목표를 상담·신청·구매 등 관찰 가능한 행동으로 정합니다.
- [ ] **02-2 메뉴 구조·페이지 구성 설계**
  전체 페이지 목록과 각 페이지의 역할·주요 내용·이동 목적지를 정합니다. 공개 홈페이지와 내부 운영 대시보드의 메뉴를 분리합니다.
- [ ] **02-3 핵심 콘텐츠·전환 흐름 기획**
  유입 채널에서 첫 화면, 서비스·사례 확인, 진단·문의, 완료 화면까지 경로를 그립니다. 각 화면의 주 행동 버튼과 연결 페이지를 정합니다.
- [ ] **02-4 와이어프레임·구성도 정리**
  PC·모바일의 주요 화면을 간단한 배치도로 만듭니다. 실제 구현 전 빈 화면·오류·로딩 상태와 관리자 수정 범위도 함께 정합니다.

완료 조건: 페이지 지도, 주요 화면 배치, 고객 이동 경로, 관리자 수정 범위가 합의되어 실제 제작 시 구조를 다시 추측하지 않아도 됩니다.

현재 기록: ZERO BUSINESS의 과거 홈페이지 기획 인수인계와 기술 개발 A-02의 SaaS 대시보드 설계를 분리해 관리합니다. 기술 A-02의 최종 메뉴·사용 흐름·완료 조건은 아직 정리가 필요합니다.

## 전체 03 Welcome Screen

목표: 처음 방문한 사람이 서비스의 가치와 다음 행동을 이해하게 만듭니다.

- [ ] **03-1 메인 히어로 카피·비주얼 구성**
  고객에게 주는 결과 중심으로 제목·설명·대표 이미지를 정합니다. 실제 홈페이지·콘텐츠·운영의 연결을 보여주며, 과거에 합의한 디자인 기준과 대조합니다.
- [ ] **03-2 핵심 가치·혜택 메시지 작성**
  어떤 고객에게 어떤 도움을 주는지 구체적으로 작성합니다. 실제 제공 기능과 향후 계획을 구분하고, 사례·설명과 연결합니다.
- [ ] **03-3 단일 CTA 성장 방향 찾기 설정**
  주 행동을 하나로 정하고 진단 또는 안내 페이지와 연결합니다. 클릭 후 예상되는 일을 짧게 안내하고, 클릭과 다음 단계 도달을 확인할 수 있게 합니다.
- [ ] **03-4 PC·모바일 반응형 최적화**
  작은 화면에서 제목·버튼·이미지 순서, 읽기 크기, 메뉴 겹침, 가로 스크롤을 확인합니다. 키보드 이동과 이미지 대체 설명도 점검합니다.

완료 조건: 처음 보는 사용자가 서비스의 대상·가치·다음 행동을 설명할 수 있고, 주요 화면 크기에서 CTA를 정상적으로 이용할 수 있습니다.

## 전체 04 인터랙티브 흐름

목표: 방문자의 상태를 파악하고 적절한 서비스·상담으로 연결합니다.

- [ ] **04-1 진단·설문·선택형 흐름 설계**
  질문·선택지·필수 입력·분기 규칙을 정합니다. 이전 단계 이동, 다시 시작, 중간 이탈 시 처리도 설계합니다.
- [ ] **04-2 단계별 안내·결과 페이지 구성**
  진행 상황, 선택 내용, 추천 이유, 우선 과제, 다음 행동을 표시합니다. 점수만 제시하지 않고 사용자가 결과를 이해할 수 있게 설명합니다.
- [ ] **04-3 사용자 맞춤 콘텐츠 연결**
  결과별 서비스·쇼룸·가이드를 연결합니다. 조건에 맞는 자료가 없는 경우에도 빈 화면 대신 기본 안내를 제공합니다.
- [ ] **04-4 데이터 수집·활용 방식 설정**
  필요한 입력만 수집하고 진단 결과와 상담 기록을 연결할 방법을 정합니다. 동의·보관·삭제·익명 분석 기준을 해당 운영 정책과 맞춥니다.

완료 조건: 대표 고객 유형별로 처음부터 결과·상담 연결까지 시험하고, 잘못된 입력·뒤로 가기·반복 제출이 일관되게 처리됩니다.

## 전체 05 설명형 랜딩 페이지

목표: 고객이 서비스 범위와 가치를 이해하고 문의 여부를 판단하게 합니다.

- [ ] **05-1 핵심 서비스·혜택 정리**
  서비스별 대상, 제공 결과, 포함·제외 범위, 필요한 자료를 정리합니다. 가격·기간을 표시한다면 산정 기준과 조건을 함께 정합니다.
- [ ] **05-2 문제 → 해결 → 결과 구조로 구성**
  고객 문제와 해결 방법, 진행 절차, 기대 결과를 연결합니다. 실제 사례와 설명용 예시를 구분합니다.
- [ ] **05-3 전환 상담·신청 유도 요소 배치**
  상담 버튼·폼·FAQ·완료 화면을 연결합니다. 접수 결과 안내, 관리자 알림, 중복 접수 처리까지 시험합니다.
- [ ] **05-4 SEO 기본 세팅 제목·설명·구조**
  페이지별 검색 의도, 제목·설명·주소·주제목·내부 연결을 정리합니다. 검색 공개 설정과 사이트맵 반영 여부를 확인합니다.

완료 조건: 고객이 제공 범위를 이해할 수 있고, 페이지에서 신청한 정보가 담당자에게 전달되는 전체 경로가 확인됩니다.

## 전체 06 쇼룸 사례 갤러리

목표: 실제 사례와 데모를 통해 제작 방식과 적용 결과를 보여줍니다.

- [ ] **06-1 서비스 유형별 쇼룸 구성 3유형**
  기존에 합의한 전문 서비스형·기업/B2B형·매장/지역 비즈니스형 분류와 대조합니다. 유형별로 대표 사례와 고객 문제를 선정합니다.
- [ ] **06-2 목록 페이지 썸네일·카드 제작**
  카드 정보·필터·정렬·빈 목록·모바일 배치를 정합니다. 실제 프로젝트·자체 쇼룸·파일럿을 표시해 구분합니다.
- [ ] **06-3 상세 페이지·데모 연결**
  프로젝트 배경, 문제, 해결 방향, PC·모바일 화면, 확인된 결과를 정리합니다. 실제 사이트·데모·관련 상담으로 연결합니다.
- [ ] **06-4 지속적인 사례 업데이트 체계**
  관리자 등록 양식, 이미지 규격, 자료 사용 범위, 수정 절차를 정합니다. 끊긴 데모 링크와 오래된 설명을 점검할 주기를 정합니다.

완료 조건: 대표 사례를 목록에서 찾아 상세·데모·상담까지 이동할 수 있고, 관리자가 새 사례를 등록할 수 있습니다.

## 전체 07 섹션 라이브러리

목표: 반복 사용하는 화면 구성을 일관된 품질로 재사용합니다.

- [ ] **07-1 핵심 섹션 템플릿 제작**
  히어로·서비스·혜택·사례·FAQ·문의 등 실제 필요한 섹션부터 만듭니다. 제목·이미지·버튼·모바일 변형과 공통 간격을 정합니다.
- [ ] **07-2 카테고리별 섹션 분류**
  목적과 사용 위치별로 분류하고 미리보기·사용 예시를 붙입니다. 비슷한 템플릿이 늘면 통합 기준을 적용합니다.
- [ ] **07-3 관리자에서 손쉬운 삽입 구조**
  워드프레스 편집 환경에 맞게 삽입·문구 수정·이미지 교체를 연결합니다. 내용 수정으로 공통 레이아웃이 쉽게 깨지지 않게 합니다.
- [ ] **07-4 신규 섹션 추가·관리 체계**
  이름·버전·지원 환경·변경 이력을 기록합니다. 공통 섹션 업데이트가 기존 페이지에 미치는 영향과 복구 방법을 확인합니다.

완료 조건: 서로 다른 페이지에서 같은 섹션을 재사용하고 내용을 수정해도 PC·모바일 배치와 공통 스타일이 유지됩니다.

## 전체 08 Zero Content OS 콘텐츠 자동화

목표: 키워드와 작업을 관리하고, 콘텐츠 생성·검토·워드프레스 저장을 연결합니다.

- [ ] **08-1 키워드 분석·추천 기능**
  사이트별 키워드 분리, 등록·검색·선택·중복 방지, 삭제 시 작업 이력 보존을 유지합니다. 다음으로 검색 의도·주제·우선순위·추천 근거를 관리하고, 분석에 사용할 자료와 비용을 결정합니다. 현재는 키워드 관리가 구현됐으며 분석·추천 엔진은 아직 없습니다.
- [ ] **08-2 AI 콘텐츠 작성·최적화 SEO/AEO/GEO**
  사이트별 사실 자료·문체·금지 내용·글 구성 기준을 정합니다. 제목·본문·FAQ·메타 설명을 생성하고 편집·검토할 수 있게 하며, 사실 검증·누락·반복·출처 확인 기준을 적용합니다. API 비밀키는 서버에서 관리하고 사용량·비용·실패 처리를 표시합니다. 생성 기능은 아직 미구현입니다.
- [ ] **08-3 워드프레스 자동 발행·예약 발행**
  사이트 등록·실제 인증·권한 확인을 거쳐 우선 초안 전송을 연결합니다. 콘텐츠와 WP 글 ID를 대응시키고, 실제 사용자 요청에 따라 공개·예약 기능을 나중에 검증합니다. 시간대, 취소·수정, 응답 유실, 중복 전송, 권한 만료를 처리합니다. 현재 성공한 것은 고정 문구의 테스트 초안 저장이며, 실제 공개·예약 발행은 미검증입니다.
- [ ] **08-4 품질 검수·중복 방지·이력 관리**
  작업 상태와 허용되는 상태 전환, 검토·보류·실패·재시도 기준을 정합니다. 비슷한 글의 중복 검사와 요청 중복 방지를 구분합니다. 작업 입력·생성본·수정본·저장 결과·오류를 추적하고 복원·재처리 방법을 마련합니다. 현재는 수동 대기열과 단일 서버의 테스트 초안 중복 방지 일부만 구현돼 있습니다.

완료 조건: 선택한 키워드로 작업을 만들고, 실제 콘텐츠 생성·검토·수정을 거쳐 올바른 사이트에 초안으로 저장하는 흐름을 반복 검증합니다. 공개·예약 기능을 이 단계 범위에 포함하기로 하면 그 기능도 별도 실증해야 전체 완료로 표시합니다.

현재 기술 개발의 다음 정리: 기술 A-02 대시보드의 메뉴·화면별 기능·완료 조건을 먼저 맞춥니다. 사이트 설정에 둘 연결 테스트와 매일 사용할 콘텐츠 작업 화면을 구분합니다. 이 문서 작성이 후속 기능 구현 착수를 의미하지는 않습니다.

- [ ] **09-2 콘텐츠 배포·색인·인덱스 관리**
  콘텐츠별 게시 위치·주제·발행 상태·URL을 관리합니다. 중복 페이지·깨진 링크·오래된 정보·검색 유입 없는 페이지의 수정·통합 기준을 정합니다.
- [ ] **09-3 외부 채널 SNS·블로그 등 연계**

- [ ] **09-4 유입 경로 분석·개선**
  검색·SNS·블로그·광고의 방문 경로를 구분합니다. 방문 수 외에 진단 완료·문의·계약 등 결과를 보고, 다음에 늘릴 채널과 수정할 페이지를 결정합니다.

완료 조건: 적어도 선정된 핵심 채널에서 실제 방문과 후속 행동을 측정하고, 그 자료로 개선 작업을 결정할 수 있습니다.

  지난 기간의 결과·실패·비용·배운 점을 요약합니다. 다음 기간의 소수 우선 작업과 완료 조건을 정해 같은 체크리스트에 반영합니다.

## 전체 13 추가 기능 및 전략 검토 추후 반영

원본의 성격을 유지합니다. 1~12단계 이후 확장 검토 항목이며, 다섯 가지를 무조건 모두 개발해야 한다는 뜻이 아닙니다. 각 항목은 채택 또는 보류의 이유를 기록합니다.

- [ ] **13-1 티스토리 연계**
  티스토리와 WP의 독자·콘텐츠 역할을 구분하고, 연결할 글과 최종 목적지를 정합니다. 채널별 표현·링크·유입 측정 방법을 마련해 소규모로 효과를 확인합니다.
- [ ] **13-2 홈페이지 속도 향상**
  핵심 페이지·기기·측정 조건을 정해 병목을 찾습니다. 이미지·캐시·코드·플러그인을 순서대로 조정하고 기능·디자인이 유지되는지 재검사합니다. 전체 01의 기본 점검을 반복 집계하지 않고 추가 개선 결과를 남깁니다.
- [ ] **13-3 네이버 지식iN**
  실제 고객 질문과 제공 서비스의 관련성을 정리합니다. 도움이 되는 답변 자료와 운영 기준을 만들고, 반응과 방문 효과를 측정할 방법을 결정합니다.
- [ ] **13-4 페이스북 그룹**
  자체 그룹 운영과 외부 그룹 참여 중 목적에 맞는 방식을 선정합니다. 대상·운영 규칙·콘텐츠·질문 대응·홈페이지 연결 흐름을 정하고 관리 부담과 효과를 비교합니다.
- [ ] **13-5 광고 운영**
  네이버·구글·메타 중 목표 고객에 맞는 채널을 고릅니다. 광고 목표·예산·중단 조건·소재·랜딩페이지·전환 측정을 먼저 정하고, 실행 결과의 비용·문의 품질·계약을 비교해 확대 여부를 결정합니다.

완료 조건: 각 후보에 채택·보류 판단과 근거가 있습니다. 채택한 항목은 실행 범위·비용·측정 기준을 정하고 실제 시험 결과까지 남깁니다. 보류도 정식 결정으로 인정합니다.

## 모든 단계에서 공통으로 지킬 개발 완료 기준

1. 시작 전에 이번 단계의 대상·범위·제외 범위·확인할 결과를 적습니다.
2. 설계 합의, 코드 구현, 모의 테스트, 실제 환경 검증을 별도로 기록합니다.
3. 기존 데이터·기능을 보존하고 백업·복구 방법을 확인합니다.
4. 비밀번호·토큰을 화면·브라우저 저장소·백업 JSON·공유 문서에 담지 않습니다.

6. 운영 공개 전에는 계정별 권한·정보 분리, 오류·장애·복구, 접근성·모바일, 사용자 안내를 검증합니다.
7. 변경 파일·버전·검증 결과·남은 문제와 다음 시작점을 기록합니다.
8. 다음 단계 이동은 해당 완료 조건을 확인하고 사용자와 정리한 뒤 결정합니다.
