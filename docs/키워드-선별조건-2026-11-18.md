# 키워드 선별 조건 구현

A-02의 키워드 세부 기능, 6단계 중 4~6의 조건 적용. 기술 주단계는 계속 A-02 진행 중.

Python keyword_rules.evaluate/enforce에 네이버 500/3000/10000 경계 및 양쪽 1페이지 확인·한쪽 이상 WP/Tistory 근거를 구현. 중앙 bank stage/read/list/attach/review/handoff/queue/export에 적용. 기존 검색량 없는 활성 기록도 사용·작성으로 우회할 수 없음. 실패 검색은 기존 증거를 파괴하지 않고 verification incomplete + 사용 제외로 기록. 월별 runner는 활성/제외 기록을 검사하며 스케줄 설치는 아직 없음.

POST /api/keyword-bank/{id}/volume: revision CAS, naverMonthly 정수 또는 null, googleMonthly 참고 정수 또는 null, 출처 필수. owner session/CSRF 보호. source/method/checkedAt 저장. provider 자동 조회는 구현되지 않음. 리뷰 활성 요청도 정책 검사하고 수동 제외는 보존. 기존 작성 준비의 eligible은 현재 조건으로 다시 계산. 원본 작성 서버는 기존 queue gate를 재사용.

React KeywordRulePanel: 조건·제외 사유·검색량 구간, 수동 입력, 출처·확인일, 양쪽 검색 열기, 대상 원문/위치/확인일 표시. CentralKeywordBank 기본 필터는 active이며 excluded 원본은 별도 필터. Sites GuidedKeywords에도 동일 패널 및 예시 API 게이트를 적용. Sites의 JS 정책은 Python 경계/게이트와 같은 계약으로 검사. 화면 시뮬레이션 숫자는 실제 검색량 아님.

검증: Python 전체 147개 통과, 기존 UI39개 통과; Sites18개 통과; React 빌드 통과. 추가 브라우저 검증은 배포 기록 참조. 실제 Render/SerpApi/검색량 제공처/WordPress 요청 없음. .state·기존 초안·사용자 데이터 초기화 없음.
