# A-02 화면·사용 흐름·완료 기준

2026-11-13 · 상세 화면 검토용 기준안. 제품 상위 구조·Python 유지·본인용 비공개는 이미 확정됐으며 [프로젝트 고정 기준](프로젝트-고정기준.md)을 따른다. 세부 메뉴·상태 조건은 별도 검토 대상이다.

## 기준과 현재 확인 범위

A-02는 SaaS 관리자 대시보드 설계다. A-1/A-2는 사이트 슬롯, A-01~A-04는 기술 단계, 전체 01~13은 사업 로드맵이다. UI 버전 v0.2.2·저장소 화면 v0.2.3·연결 서버 v0.2.5는 별개이며 하나의 전체 제품 버전으로 오인하지 않는다.

현재 사용자의 화면은 한 페이지 안에 사이트 등록·키워드·작업·백업을 배치한다. 좌측 메뉴에는 대시보드·키워드 관리·AI 콘텐츠·발행 관리·작업 기록·설정이 있으나 App.tsx에서 별도 화면 이동 핸들러가 없는 표시용 버튼이다. 메뉴 표시와 구현 완료를 분리해야 한다.

## 제안하는 운영 화면

| 화면 | 사용자가 하는 일 | 현재 구현·증거 | 다음 완료 조건 |
|---|---|---|---|
| 대시보드 | 선택한 사이트·작업 현황 확인 | 사이트별 키워드·대기 작업 수. AI·발행 수는 0 표시 | 실제 값/미구현 값 구분, 선택 사이트 일관성, 빈 상태 안내 |
| 사이트 관리 | 이름·주소 등록, 연결·권한 확인, 테스트 초안 | A-1 사용자 PC 인증·권한·초안 738·재사용 확인. A-2 미검증 | 중앙 자격 저장 흐름·확인 시각·불확실 결과·credential revision 기준 확정 |
| 키워드 관리 | 등록·검색·선택·삭제·작업 등록 | A-1/A-2 로컬 분리 및 회귀 테스트 | 중앙 사이트 ID로 분리, 중복 정책·삭제 범위·실패 시 보존 확정 |
| 작업·기록 | 대기·취소·재등록·상태 필터 | 로컬 작업 등록/취소/재등록 구현. AI 실행 없음 | 서버 상태 전이·이력·동시 수정 충돌·권한 기준 확정 |
| 백업·복원 | 파일 백업·형식 검사·미리보기·복원 | 저장소에 v1/v2 JSON·수동 SQLite 저장본 구현. 실제 PC 백업 완료는 미확인 | v1/v2 차이·초안 DB 별도 보존·이관 충돌·롤백·서버 보관 실패 안내 |
| 설정·운영 상태 | 서비스 버전·저장 위치·연결 상태·계정 확인 | 실제 상태 화면은 없음, 실행 창에 서버 버전 | 화면/API/DB 버전과 로그인·저장 상태를 비밀 없이 확인 |

기존 AI 콘텐츠·발행 관리 메뉴는 별도 범위가 확정될 때까지 `준비 중`으로 안내하는 안을 제안한다. 사용 가능한 기능처럼 클릭시키고 아무 반응이 없게 두지 않는다. 이 문서 작성만으로 실제 메뉴를 바꾸지 않았다.

## 사이트 연결 상태와 문구

| 상태 | 사용자에게 보일 뜻 | 진행 가능 동작 |
|---|---|---|
| 미등록 | 사이트 이름·주소 없음 | 등록 |
| 등록됨·미검증 | 저장은 됐지만 실제 인증은 확인 전 | 자격 등록·연결 확인 |
| 확인 중 | 요청 진행 중 | 중복 확인 클릭 방지, 다른 작업 영향 최소화 |
| 인증 확인 | 같은 사이트와 사용자 인증을 확인 시점에 성공 | 권한 확인 |
| 권한 확인 | 글 작성·발행 capability의 true/false/unknown | 작성 true인 경우만 초안 확인 단계 |
| 초안 저장 확인 대기 | 실제 저장 대상·제목·본문 제시 | 사용자 확인 후 1회 요청 |
| 저장 결과 불확실 | 시간 초과·응답 유실 등으로 생성 여부를 단정 못함 | 자동 재생성 금지, 조회·관리자 확인 경로 |
| 초안 저장 확인 | 생성한 ID를 재조회해 draft 확인 | 같은 ID 상태 확인·WP 편집 링크 |
| 기존 초안 확인 | 기존 기록 ID가 여전히 draft | 새 글 생성 없이 재확인 |
| 연결 실패·권한 미확인 | 거부·네트워크·서버 미실행 등 | 안전한 오류·다음 한 단계 안내 |

`draft`는 공개되지 않은 초안 상태이며 WordPress의 별도 상태인 `private`와 혼용하지 않는다. 이번 테스트는 draft만 사용한다. 작성·발행 capability가 true여도 실제 공개 발행 완료로 표시하지 않는다.

사이트 주소·자격이 바뀌면 기존 인증 결과를 현재 성공처럼 유지하지 않는다. 저장 실패·확인 요청 실패·상태 불확실을 `저장 완료`로 표시하지 않는다. 별도 PC에서 로그인이 됐다는 이유로 예전 연결 확인 시각을 현재 인증으로 갱신하지 않는다.

## 서버 저장·복원 화면의 필수 안내

- 현재 로컬 모드는 브라우저·서버 폴더에 데이터가 나뉜다. 중앙 모드와 구분한다.
- v1 JSON은 키워드·작업만, v2는 사이트 이름·주소도 포함한다. 둘 다 비밀번호와 초안 DB를 포함하지 않는다.
- 서버 보관은 현재 버튼을 눌렀을 때 저장본을 추가하는 기능이다. 자동 동기화나 자동 백업으로 표현하지 않는다.
- 원본 손상·저장 공간 부족·서버 미실행 시 상태를 명확히 표시한다.
- 복원은 원본 개수·대상 사이트·변경 범위·충돌을 미리 보여준다. 고객 데이터 삭제와 같은 결과가 생기는 전체 교체는 명시적으로 확인한다.
- 중앙 전환 시 로컬 데이터를 자동으로 비우거나 서버의 빈 데이터로 덮어쓰지 않는다.

## 다음 개발 묶음 제안

1. 이 화면 기준과 중앙 운영 범위를 검토해 A-02 설계를 확정한다.
2. 사이트·키워드·작업·백업을 서버에 보관하는 API 계약을 확정한다.
3. 로그인·소유권·데이터 저장을 먼저 구현하고, 기존 화면을 API에 연결한다.
4. 중앙 연결·초안 재사용·이관·다른 PC 검증을 수행한다.
5. AI 생성·공개/예약 발행은 기존 로드맵의 해당 범위와 대조한 뒤 착수한다.
