# ZERO SEO OS v0.2.2 — 테스트 초안 저장

## 이번 변경

기존 키워드·작업 대기열·JSON 백업/복원 코드는 유지했습니다. v0.2.0의 실제 인증 확인과 v0.2.1의 작성·발행 권한 조회에 이어, 테스트 글 1개를 초안으로 저장하는 기능을 추가했습니다.

- 대상 사이트·제목·본문을 보여주고 화면 안의 확인 버튼을 누른 뒤에만 요청합니다.
- 서버가 글 작성 권한을 다시 확인합니다.
- WP에 `POST /wp-json/wp/v2/posts`를 보내며 서버에서 `status: draft`를 고정합니다. 브라우저가 임의 상태·제목·본문을 지정할 수 없습니다.
- 생성 응답의 글 ID와 초안 상태를 검사하고, 같은 글을 다시 GET 조회해 초안 상태를 확인한 뒤 성공으로 표시합니다.
- 같은 사이트에 반복 클릭·동시 요청으로 중복 생성하지 않도록 서버에 처리 기록을 남깁니다. A-1과 A-2에 같은 URL을 등록해도 이 서버 기록 내에서는 한 번만 생성합니다.
- 기존 초안의 상태를 확인할 때도 새로 조회합니다. 삭제·권한 변경·상태 변경 시 성공으로 표시하지 않습니다.
- 키워드와 대기열을 소비하지 않는 별도의 연결 테스트입니다. AI 생성이나 공개 발행 기능은 추가하지 않았습니다.

## 1. 기존 v0.2.1에서 업데이트

1. 현재 앱의 **전체 데이터 백업 다운로드**로 키워드·작업 JSON을 보관합니다.
2. VS Code에서 실행 중인 화면 서버와 Python 연결 서버 터미널에서 각각 Ctrl+C를 누릅니다.
3. 기존 프로젝트는 복사해 백업합니다. 원래 위치의 폴더를 옮기거나 삭제하지 마세요.
4. ZIP의 `frontend`와 `backend`를 기존 `ZERO_SEO_OS` 안에 붙여넣고 같은 파일을 교체합니다.
5. 기존 `.git`, `frontend/node_modules`, 향후 생성되는 `backend/.state`는 그대로 유지하세요.

이번 버전은 의존성 변경이 없으므로, 기존 앱이 실행되던 PC에서는 `npm.cmd ci`를 다시 할 필요가 없습니다.

## 2. 화면 실행

VS Code 터미널 첫 번째 창:

```powershell
cd C:\Users\정의용\Desktop\ZERO_SEO_OS\frontend
npm.cmd run dev
```

http://127.0.0.1:5173/ 을 열거나 기존 화면을 새로고침합니다. 이 주소와 포트를 사용하세요. localhost와 127.0.0.1은 브라우저 데이터 저장 공간이 다릅니다.

완전히 새로 설치해서 node_modules가 없는 경우에만, 서버를 모두 종료한 상태에서 frontend 폴더의 `npm.cmd ci`를 먼저 실행합니다. EPERM 파일 잠금 오류가 나면 다른 터미널에서 실행 중인 화면 서버가 있는지 확인합니다.

## 3. 연결 서버 실행

VS Code 터미널의 + 버튼으로 두 번째 터미널을 엽니다. 아래 명령은 수정하지 않고 그대로 입력합니다.

```powershell
cd C:\Users\정의용\Desktop\ZERO_SEO_OS\backend
python -c "import os,getpass,runpy; os.environ['ZERO_WP_A1_URL']=input('1. Site URL: ').strip(); os.environ['ZERO_WP_A1_USER']=input('2. WP username: ').strip(); os.environ['ZERO_WP_A1_APP_PASSWORD']=getpass.getpass('3. App Password: ').strip(); runpy.run_path('server.py',run_name='__main__')"
```

명령 실행 뒤 질문이 나오면 주소 → WP 사용자명 → 앱 비밀번호를 입력합니다. 앱 비밀번호는 화면에 별표도 나오지 않는 것이 정상입니다. 사용자명과 이메일이 같은 계정은 그 사용자명을 그대로 사용하세요. 평소 로그인 비밀번호 대신 WordPress의 Application Password를 사용합니다.

Python 3.11 이상이 필요합니다. 별도 Python 패키지 설치는 없습니다. `python` 명령이 없고 Python Launcher가 있으면 `py -3`으로 바꿀 수 있습니다. A-1/A-2를 모두 설정하려면 함께 제공한 `backend/Start-Connector.ps1`을 사용할 수도 있습니다.

환경변수 이름은 A-1의 경우 ZERO_WP_A1_URL / ZERO_WP_A1_USER / ZERO_WP_A1_APP_PASSWORD이며, A-2는 A2로 바뀝니다. 서버는 이름·주소 외의 자격증명을 브라우저에 받거나 전달하지 않습니다. 비밀번호를 채팅이나 소스 파일에 적지 마세요.

## 4. 테스트 초안 저장

1. 앱에서 A-1을 선택합니다. 기존 등록 이름과 주소가 보이는지 확인합니다.
2. **글 작성·발행 권한 확인**을 눌러 글 작성 권한이 있음으로 나오는지 확인합니다.
3. **테스트 초안 1개 저장**을 누릅니다.
4. 대상 사이트·제목·본문을 확인하고 **확인하고 초안 저장**을 누릅니다. 취소하면 요청하지 않습니다.
5. **테스트 초안 저장 확인 · 글 ID … · 상태: 초안**이라는 결과를 확인합니다.
6. **워드프레스에서 초안 확인** 링크로 관리자 편집 화면을 열어 직접 확인할 수 있습니다. 로그인 화면이 나오면 해당 워드프레스에 로그인합니다. 공개 발행 버튼은 누르지 않습니다.

테스트 제목: `[ZERO SEO OS] 연결 테스트 초안`

본문: `ZERO SEO OS와 워드프레스의 초안 저장 연결을 확인하기 위한 테스트 글입니다.`

두 번째 요청은 기존 기록이 있으면 새 글을 만들지 않고 해당 글을 조회합니다. 글 상태 확인은 확인 시각 기준입니다. 앱 새로고침 후에는 권한 확인이 다시 필요하며, 화면에는 상태 미확인으로 표시합니다. 서버에 저장 기록이 남아 있으면 다시 요청해도 기존 글을 확인합니다.

## 5. 실패·중복 방지 기록

- `backend/.state/test-drafts.sqlite3`에 대상 URL, 생성 시각, 확인된 글 ID를 저장합니다. 비밀번호·토큰은 포함하지 않습니다. Git에서 제외합니다.
- **이 폴더를 유지해야 중복 방지 기록이 유지됩니다.** 다른 PC로 옮기거나 업데이트할 때도 필요하면 프로젝트 백업과 함께 보관하세요. 키워드·작업 JSON 백업에는 이 기록이 포함되지 않습니다.
- 서로 다른 PC/서버는 기록을 공유하지 않으므로 각각 실행하면 별도 테스트 초안이 생길 수 있습니다.
- 생성 요청의 응답을 받지 못하면, WP에서 이미 저장했을 가능성이 있어 해당 사이트의 추가 생성을 차단합니다. 이 경우 관리자 글 목록에서 테스트 제목을 먼저 찾아보세요. 기록 파일을 삭제해 재시도하지 마세요. 필요하면 결과를 공유해 복구를 진행합니다.
- 글 ID를 받은 뒤 후속 조회만 실패했다면 다음 요청은 해당 ID만 조회하며 다시 만들지 않습니다.
- 기존 테스트 글이 삭제·공개 발행 등으로 바뀌었으면 추가 생성하지 않고 오류를 표시합니다.
- 서버는 초안 상태로만 요청합니다. WP 플러그인이 상태를 강제로 바꾸면 초안이 아니라는 오류를 표시하므로 관리자에서 즉시 확인해야 합니다.

## 보안과 범위

연결 서버는 개인 PC 개발용으로 127.0.0.1:8765에만 엽니다. 지정된 화면 Origin·Host를 검사하고, 서버에 설정한 HTTPS URL과 일치하는 공개 인터넷 대상에만 접속합니다. DNS 확인 후 검증한 IP로 접속하며 원래 호스트의 TLS 인증서를 검증합니다. 리다이렉트와 내부망 주소는 차단합니다.

브라우저에는 이름·주소만 저장하며 앱 비밀번호는 서버 프로세스 환경변수에만 둡니다. 워드프레스 사용자 상세 정보·비밀번호·토큰은 화면 응답이나 로그로 반환하지 않습니다. 실제 계정 비밀번호를 채팅에 노출했다면 폐기·변경하세요.

외부 공개/SaaS 운영에는 사용자 로그인, 계정별 사이트 소유 검증, 비밀 저장소, 배포용 HTTPS API가 추가로 필요합니다.

- 기존 App.tsx의 키워드·대기열·JSON 백업/복원 함수는 원본과 동일함을 비교했습니다.
