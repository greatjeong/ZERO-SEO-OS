# ZERO SEO OS 개발 기준 — 원래 로드맵 유지

개발 전 [프로젝트 고정 기준](프로젝트-고정기준.md)을 먼저 적용한다. 이미 합의한 제품 구조·Python 유지·본인용 비공개·호스팅 구분은 재질문하지 않는다.

## 최신 확인: 2026-11-13

주 단계는 A-02 진행 중이다. 아래 초기 항목은 11월 12일 당시 기록이며 최신 검증을 덮어쓰지 않는다.

- 연결 서버 v0.2.5로 사용자 PC A-1 인증·작성/발행 capability 확인, 초안 738 생성·재조회·같은 ID 재사용 확인.
- 현재 저장소의 서버 테스트 48개, 화면 로직 테스트 7개, 빌드·lint 통과. 실제 브라우저 E2E는 미완료.
- 사용자 PC 화면 v0.2.2와 저장소 최신 화면은 다를 수 있다. 실제 데이터 JSON 백업은 확인 전이다.
- 사용자 부재 중 [중앙 운영 전환 설계](중앙운영-전환설계.md), [A-02 화면·완료 기준](A-02-화면-완료기준.md), [코드 점검 결과](중앙전환-점검결과.md)를 검토용으로 준비했다. 중앙 배포·로그인·공유 DB를 구현한 것은 아니다.
- 본인용 비공개·Python 유지·Cloudways는 테스트 WP 호스팅이라는 구분은 확정됐다. 다음은 고정 기준 안에서 실제 Python 운영 환경·주소와 A-02 세부 완료 조건을 구체화한다. 사업 전체 01~13 진행률은 변경하지 않는다.

기록 기준: 2026-11-12, 사용자가 제공한 「개발 진행 현황 대시보드 / PHASE A · 시스템 기반 구축」 이미지와 이 대화에서 확인한 실제 결과.

추가 기록: 사용자가 별도의 「통합 실행 로드맵 13단계」 이미지도 제공했습니다. 전체 사업 01~13과 이 문서의 기술 A-01~A-04는 별도 번호 체계입니다. 전체 사업의 원본 53개 항목을 유지한 [상세 체크리스트](ZERO-통합로드맵-13단계-상세체크리스트.md)를 검토용 초안으로 작성했습니다. 이것은 찾지 못한 예전 Word 마스터 플랜의 복구본이 아닙니다. 사용자는 원본 탐색을 중단하고 진행하기로 했습니다. 기술 주 단계 A-02 상태는 변경하지 않았습니다.

## 현재 주 개발 단계

**A-02 SaaS 관리자 대시보드 설계 — 진행 중.**

A-1 / A-2는 워드프레스 사이트 구분이다. 개발 단계 A-01 / A-02와 혼동하지 않는다. v0.2.2는 배포 파일 버전이며 개발 단계 번호가 아니다.

## 원래 개발 순서

| 구분 | 사용자 로드맵의 명칭 | 현재 해석 |
|---|---|---|
| A-01 | 공통 데이터 모델 및 운영 정책 | 기존 로드맵에서 설계 완료. 모든 정책·DB·계정 기능의 구현 완료를 의미하지 않음 |
| A-02 | SaaS 관리자 대시보드 설계 | 현재 주 단계. 일부 화면 구현, 최종 구조·사용 흐름 정리 필요 |
| A-03 | 워드프레스 연결 플러그인 설계·개발 | 연결 일부 선행 구현. Python 서버 + WP 기본 REST API이며 전용 플러그인은 미구현 |
| A-04 | SaaS ↔ 워드프레스 연결 테스트 | 로컬 앱의 A-1 연결 일부 선행 검증. 전체 완료 아님 |
| PHASE B | 1~5단계 기능 개발 | 상세 범위는 원래 계획 확인 후 진행. 임의로 세부 항목을 만들어 확정하지 않음 |
| PHASE C | 6~8단계 기능 개발 | 대기 |
| PHASE D | 9~12단계 기능 개발 | 대기 |
| PHASE E | 통합 테스트·보안·출시 | 대기 |

원본의 ‘약 8%’는 당시 이미지의 표시다. 현재 완료율로 재사용하거나 새 수치를 임의로 산출하지 않는다.

## A-01 원본 설계 항목

- 고객 계정 및 로그인 운영 정책
- 워드프레스 사이트 연결 및 권한 구조
- 사이트별 키워드 완전 분리 관리(A안 확정)
- AI 작업(생성·품질검사·재시도) 정책
- 콘텐츠 발행(예약·자동·수동·기록) 정책
- 데이터 보관·복구·삭제 정책
- 공통 데이터베이스 구조 및 관계 설계
- 정책 간 충돌 점검 및 검증 기준 정리

원본에 완료로 표시된 설계 항목이며, 현재 코드의 구현·운영 검증 여부와 분리해 판단한다.

## 현재까지 실제 구현·확인한 내용

- A-1/A-2 키워드 관리, 작업 대기열 등록·취소·재등록, 키워드·작업 JSON 백업/복원 유지.
- 사이트별 이름과 HTTPS 주소 등록 화면.
- 브라우저에는 WP 비밀번호·토큰을 저장하지 않고 Python 서버 프로세스 환경변수 사용.
- A-1 실제 WP 인증 성공. 사용자 보안 가드를 켠 상태에서도 인증 성공.
- A-1 사용자 권한 조회에서 작성·발행 권한 있음 확인.
- v0.2.2에서 실제 테스트 글 ID 737 저장. 서버가 재조회하여 draft 상태 확인. 사용자가 제목과 본문 확인.
- 공개 발행·예약 발행은 실행하지 않음. A-2 실제 사이트는 미검증.
- 중복 방지 기록은 backend/.state에 저장. 동일 서버 기록이 유지되는 범위에서 적용하며 여러 PC 간 공유되지 않음.
- 최종 코드 빌드와 서버 모의 테스트 25개 통과. 이것이 최종 제품 전체의 안정성 검증을 의미하지 않음.

## 개발이 벗어나지 않도록 지킬 기준

1. 새 작업 전에 원래 로드맵의 어느 항목인지 명시한다.
2. 현재 주 단계 A-02를 기준으로 관리 화면의 구성·역할·사용 흐름과 완료 조건을 먼저 합의한다.
3. 다른 단계의 선행 작업은 별도 기록한다. 연결 성공만으로 A-02/A-03/A-04 전체 완료를 선언하지 않는다.
4. 로드맵 범위나 주요 아키텍처 변경이 필요하면 이유와 영향을 설명하고 사용자와 합의한다. WP 전용 플러그인 요구와 현재 기본 API 연결 방식의 차이는 남은 설계 결정이다.
5. 키워드 → AI 생성 등 후속 기능을 곧바로 다음 확정 작업으로 취급하지 않는다. 원래 PHASE B~D 세부 계획과 대조한다.
6. 기존 기능과 데이터 보존을 우선한다. 변경 시 전체 교체용 ZIP과 쉬운 실행 안내를 제공한다.
7. 종료 시 단계별 완료/남은 일/다음 작업을 기록한다. 기억만을 약속하지 않고 이 기록을 갱신한다.

## 다음 재개 시 우선 확인

- A-02 대시보드의 최종 메뉴·화면별 기능 범위·사용 흐름·완료 조건을 원래 설계와 맞춰 확정한다. 세부 원본이 필요하면 해당 부분만 요청한다.
- 현재 화면과 실제 연결 시험 결과를 위 범위에 매핑한다.
- v0.2.2 코드의 Git 커밋·푸시는 이 대화에서 확인하지 않았으므로 종료 전 상태를 확인한다.
- JSON은 키워드·작업 전용이다. 사이트 설정과 서버 중복 방지 기록은 별도 보관 대상이다.
