# 중앙 전환 준비 점검 결과

2026-11-13 · 저장소 v0.2.5 연결 서버 기준 · 코드 정적 검토 및 로컬 모의 테스트

## 후속 구현 상태

아래 최초 점검 이후 [중앙 기반 v0.3.0](중앙기반-v0.3.0-구현.md)을 추가했다. 본인 로그인·세션·중앙 사이트/키워드/작업 저장·충돌 방지·가져오기 코드가 있으며 서버 67개·화면 15개 테스트와 빌드·lint가 통과했다. 실제 배포·WordPress 중앙 자격 저장/실행·초안 DB 이관·고객 격리는 아직 완료하지 않았다. 아래 `server.Handler`의 무인증 지적은 기존 로컬 서버를 그대로 공개하지 말라는 의미로 계속 유효하다. 최초 점검의 48/7 검증 수는 당시 기록이다.

## 중앙 서비스 공개 전 해결할 사항

| 우선순위 | 발견 사항·근거 | 필요한 조치·검증 |
|---|---|---|
| P0 | server.Handler에는 로그인·사용자별 인가가 없다. Host/Origin 및 loopback 제한만 있다. | 이 서버를 그대로 인터넷에 공개하지 않음. 세션·소유권을 붙인 중앙 API와 두 사용자 격리 테스트 필요 |
| P0 | 사이트 번호는 A-1/A-2 고정, 사용자 소유권 모델이 없다. | workspace/site 영구 ID와 서버 측 소유권 검증 |
| P0 | 자격은 프로세스 환경변수에만 있고 재시작 후 사용자 입력이 필요하다. | 서버 비밀 저장·키 관리·회전/복구·응답/로그 미노출 |
| P0 | 초안 intent는 각 PC의 SQLite다. JSON에 포함되지 않는다. | 새 중앙 DB에서도 재작성 전 이관·불확실 상태 보존. 737/738 이력 조정 |
| P1 | 프론트엔드 fetch 3곳이 localhost:8765에 고정돼 있다. | 중앙 모드에서 같은 출처 API로 연결. 로컬 개발 호환 분리 |
| P1 | 브라우저 localStorage가 키워드·작업·사이트 원본이다. | 서버 데이터 기준·revision 충돌 처리·실패 시 로컬/서버 보존 정책 |
| P1 | JSON 복원은 사이트와 키워드·작업을 여러 저장 작업으로 적용한다. 저장 공간 부족 시 원자적 교체 보장이 없다. | 중앙 복원은 DB 트랜잭션. 로컬 전환 전 원본 백업·검사·실패 복구 설계 |
| P1 | 손상된 로컬 원문은 시작 시 보존하지만 화면 로드에서는 유효 항목만 읽는다. 이후 사용자가 편집하면 원문 일부가 사라질 수 있다. | 손상 발견 안내·원문 내보내기·수정 전 보존을 이관 흐름에 포함 |
| P1 | 여러 서버의 동시 초안 생성은 검증하지 않았다. 현재 테스트는 같은 로컬 DB다. | 중앙 DB 유일성·동시 요청·타임아웃·프로세스 재시작 테스트 |
| P1 | 서버 저장본은 누적 보관이며 평문이다. 목록은 최근 100개만 표시한다. | 보관·용량·접근통제·운영 암호화·오래된 저장본 조회 기준 합의 |
| P1 | 현재 앱에 운영 health/version 화면이 없다. 화면·서버 버전이 다르게 배포될 수 있다. | API·화면·DB 스키마·소스 버전을 함께 확인하는 릴리스 체계 |
| P2 | 좌측 일부 메뉴는 작동 핸들러가 없다. | 준비 중 안내와 A-02 메뉴 범위 합의 |
| P2 | E2E 실행 설정이 Vitest 파일까지 읽어 실패한다. | 이번 작업에서 testMatch를 *.spec.ts로 제한해 수정 |

우선순위는 현재 코드가 로컬에서도 전부 위험하다는 뜻이 아니라 중앙 공개 전 필수 조건을 구분한 것이다. 공격 재현·침투 테스트나 보안 전체 인증은 수행하지 않았다.

## 이번에 직접 수정한 항목

Playwright의 기본 파일 탐색이 tests/ui.test.tsx를 읽어 Vitest runner 오류로 브라우저 실행 전 실패하는 것을 `npx playwright test --list`로 재현했다. playwright.config.ts에 `testMatch: '**/*.spec.ts'`를 추가한 뒤 regression.spec.ts의 E2E 2개만 탐색되는 것을 확인했다. Vitest의 include는 기존 *.test.tsx로 유지한다. 제품 기능·데이터·WordPress 요청 코드는 변경하지 않았다.

운영 서버와 사용자 PC의 데이터는 이 환경에 없다. JSON 다운로드·실제 백업·복원·중앙 배포·다른 PC 재접속은 실행하지 않았다.

## 다음 구현 전에 결정할 것

권장안은 먼저 운영자 본인용 비공개 중앙 버전으로 로그인·서버 저장·초안 이력을 구현하고, 고객 계정 공개 전에 사용자 격리를 검증하는 것이다. 중앙 웹 계층·DB·인증·호스팅의 구체 제품과 비용은 아직 선택하지 않았다. 상세 제안은 중앙운영-전환설계.md, 화면 기준은 A-02-화면-완료기준.md에 있다.

본인용 비공개·Python 유지·SaaS 호스팅의 Cloudways 제한 없음은 이미 확정됐다. 다시 묻지 않는다. 남은 선택은 이 기준에 맞는 실제 Python 운영 환경·서비스 주소와 구체 인증·DB 구현이다. 그 전에도 설계와 모의 검증은 가능하지만 실제 계정·리소스 생성·배포·PC 데이터 이관은 이 문서 작성만으로 실행하지 않는다.
