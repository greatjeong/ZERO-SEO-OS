# RSS 수집·후보 추출 첫 구현

2026-11-14 KST. 사용자가 Render·SerpApi 실제 연결을 보류하고 다른 개발을 요청했다. 키워드 6단계 중 3단계(고객 실습 로드맵 키워드 발굴·DB 기능)의 선행 구현이다. 기술 주 단계 A-02는 진행 중으로 유지한다.

## 실제 추가한 코드

- 중앙 React 화면에서 공개 HTTPS 블로그 주소 입력 → RSS 수집 요청 → 글/후보 수 표시 → 수집 기록 다시 불러오기 → 전체 JSON 다운로드.
- 서버는 블로그 HTML의 RSS/Atom alternate 선언을 탐색. 댓글 피드 제외. 동일 origin의 선언 우선, 이어 `/rss`, `/feed/` 후보로 최대3개 피드만 조회. 사이트 경로가 있으면 해당 경로 아래 기본 후보를 사용한다.
- 일반 RSS2와 Atom 피드 파싱. 공개 글 제목과 피드 분류(category)를 검토 전 후보로 보관하고 원문·피드 URL, 출처 유형을 유지한다. 제목을 핵심 검색 키워드로 확정하는 NLP 기능은 아니다. 검색량/노출 검사와 통과/탈락은 적용하지 않는다.
- 같은 후보는 NFKC·대소문자·공백 기준으로 해당 수집 건 안에서 중복을 줄이고 출처를 합친다. 별도 수집 건은 이력으로 모두 보존한다. 전역 키워드 DB 승격은 미구현.
- 같은 블로그 origin의 글만 수집. 다른 사이트 재배포 글은 귀속하지 않는다. 동일 글 URL 중복 제거. 최대1MB/500개 항목. 화면은 후보200개, JSON에는 처리된 전체 후보. RSS는 최신 글 일부만 제공할 수 있으므로 전체 사이트 수집을 보장하지 않는다.
- UTF-8 XML만 지원. DTD/ENTITY, 비정상 XML/초과 크기는 거부. 인증·프록시·리다이렉트 없이 공개 IP DNS 검증 후 고정 IP HTTPS GET만 수행. 제한 응답이나 연결 실패 뒤 경로를 바꿔 우회하지 않는다. 리다이렉트 사이트는 현재 미완료로 기록한다.
- 세션/Origin/CSRF 보호, 서버 프로세스당 수집 한 번. 수집 결과·실패를 중앙DB의 별도 `keyword_feed_collections` 테이블에 보관. 기존 키워드/작업·WordPress 737/738·.state·JSON 호환 유지. 기존 v1/v2 JSON에는 이 테이블이 포함되지 않으므로 DB 운영 백업은 별도 필요.
- 검색 API 키 없이 블로그 벤치마킹 입력으로 사용 가능. 네이버·구글 검색 단계를 검증한 것으로 취급하지 않는다. 정적 Sites 시뮬레이션 및 운영 WordPress는 수정하지 않았다.

## 확인과 남은 일

신규 서버 테스트9개: RSS·Atom, 제목/분류 출처 통합, 중복·외부 글 제외, XML/크기 제한, 댓글/타도메인 피드 제외, 제한 응답 중단, 내부DNS 차단, 재시작 보관·실패 보존, 로그인/CSRF 및 검색키 미설정 독립 동작. 기존105개 전체 테스트(신규8개 당시) 통과 후 마지막 인증 테스트 포함 신규9개 별도 통과. 화면23개, TypeScript/Vite 빌드, Python compile, diff 검사 통과.

실제 `https://namtaegi.com/`, `https://ek5524.tistory.com/` 읽기 전용 수집 시도는 모두 `connection_failed`. 이 실행 환경에서 실패한 사실만 확인했으며 사이트 자체 장애나 RSS 부재로 판정하지 않는다. 실제 수집 성공, 운영PG, Render 배포 및 중앙 화면 브라우저 E2E는 아직 미검증. 결과를 만들어 넣거나 샘플을 실제 자료처럼 저장하지 않았다.

다음은 실제 수집 결과 검증과 별도로 4단계의 조건 검사 입력·수동 선별, 최종 키워드 DB 축적·이력·재검증을 순차 연결한다. 자동 월간 스케줄/AI 원본글 생성/PBN·백링크는 이번 구현 범위가 아니다. Render·SerpApi는 사용자가 재개하기 전 보류하며 카드/키를 반복 요청하지 않는다.
