# ZERO SEO OS

워드프레스 사이트별 키워드·작업·연결을 관리하는 개발 중인 대시보드입니다. 현재는 **PC에서 실행하는 로컬 버전**입니다. 중앙 서버·로그인·회원제 SaaS는 아직 구현·배포하지 않았습니다.

## 지금 확인된 상태

- A-1/A-2 키워드 관리, 작업 등록·취소·재등록, JSON 백업·복원 소스가 있습니다.
- A-1 실제 인증, 글 작성·발행 capability 조회, 테스트 초안 738 저장·재조회·같은 ID 재사용이 사용자 PC에서 확인됐습니다.
- 서버 모의 테스트 48개와 화면 로직 테스트 7개가 통과했습니다. 실제 브라우저 E2E 전체 통과를 뜻하지 않습니다.
- A-2 실제 연결·공개/예약 발행·고객별 로그인·중앙 DB는 확인되지 않았습니다.
- 기술 주 단계는 A-02 진행 중입니다. A-1/A-2 사이트 번호와 A-01~A-04 기술 단계를 구분합니다.

## 기존 PC에서 실행

| 실행 파일 | 위치 | 역할 |
|---|---|---|
| Start-Dashboard.cmd | 프로젝트 최상위, frontend/backend와 같은 위치 | 화면 서버 127.0.0.1:5173 |
| Start-Connector.cmd | backend 폴더 | 연결 서버 127.0.0.1:8765 |

두 파일을 각각 더블클릭하고 두 창을 유지합니다. 연결 서버에는 사이트 주소·WordPress 사용자명과 해당 계정의 응용 프로그램 비밀번호를 입력합니다. 앱 이름은 사용자명·비밀번호가 아닙니다. 현재 Python 실행기는 check_wordpress.py의 마스킹 창을 재사용하므로 두 파일을 같은 backend 폴더에 둡니다. A2를 쓰지 않으면 주소 질문에서 Enter로 건너뜁니다.

브라우저에서는 http://127.0.0.1:5173 을 엽니다. 8765는 화면 주소가 아니라 화면의 요청을 처리하는 서버입니다. 앱 비밀번호·Authorization·환경변수 전체는 채팅·GitHub에 올리지 않습니다.

Python 3.11 이상과 이 프로젝트에 맞는 Node.js/npm 및 frontend 의존성이 설치된 PC를 기준으로 합니다. 실행 오류는 열린 창에 남겨 확인합니다. PowerShell 정책을 바꾸거나 Bypass를 쓸 필요는 없습니다. 기존 PS1보다 CMD 실행기를 사용합니다.

## 데이터 보존과 다른 PC

| 보관 대상 | 위치·의미 |
|---|---|
| 사이트 이름·주소, 키워드·작업 | 실행한 브라우저 localStorage |
| JSON v1 | 키워드·작업 파일 백업 |
| JSON v2 | 키워드·작업·사이트 이름·주소 파일 백업 |
| backend/.state/test-drafts.sqlite3 | 테스트 초안 중복 방지·불확실 시도 기록 |
| backend/.state/workspace.sqlite3 | 사용자가 버튼으로 추가한 서버 저장본 |
| 앱 비밀번호 | 현재 실행 프로세스와 자식 서버 메모리. 파일/JSON/Git에 저장하지 않음 |

GitHub는 코드만 보관합니다. 다른 PC에 clone했다고 데이터가 따라오지 않습니다. JSON은 초안 DB를 포함하지 않으므로 .state도 별도로 보존해야 합니다. 업데이트·정리 시 .state를 삭제하지 마세요. 실제 WordPress 글은 이관 도구나 테스트를 이유로 자동 삭제하지 않습니다.

저장소 화면 소스와 사용자가 설치한 화면은 다를 수 있습니다. v2 전체 백업·서버 보관 버튼은 최신 화면 소스의 기능입니다. 사용자 PC에서 실제 백업을 완료했는지는 아직 확인되지 않았습니다.

## 확정한 프로젝트 기준

서비스는 소개 홈페이지·App 웹앱·SaaS 중앙 운영 세 영역으로 구성하고 React/Python을 유지합니다. 첫 중앙 버전은 본인용 비공개입니다. Cloudways는 테스트 대상 WordPress의 호스팅이며 ZERO SEO OS 호스팅을 제한하지 않습니다. 이미 합의한 내용을 다시 묻지 않는 [프로젝트 고정 기준](docs/프로젝트-고정기준.md)을 개발의 출발점으로 사용합니다.
